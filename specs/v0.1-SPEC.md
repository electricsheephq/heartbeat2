# HeartBeat 2.0 (plugin id `heartbeat2`) — v0.1 implementation spec

Status: approved design (owner 2026-10-12). Source of truth for Codex implementation units U1–U4.
Evidence: internal design research (OpenClaw heartbeat failure reports, Hermes seam survey); not published.

## 0. Lane contract (applies to every unit)

- **Outcome:** a Hermes Agent plugin that lets agents and users create their own time wakes and event watchers that run IN the existing messaging conversation on the session's own model, with configurable guardrails, a no-op governor, and none of OpenClaw heartbeat-1.0's failure classes.
- **Done-when (per unit):** the unit's files exist, `.venv/bin/python -m pytest -q` (from the repository root) is green, every test listed for the unit exists and was seen RED before the implementation made it green (decisional modules), and the unit report (below) is written.
- **Resume identity:** this repository (branch `main`, remote `electricsheephq/heartbeat2`). Hermes reference source (read-only): a Hermes Agent source checkout (`$HERMES_SRC`, default `~/.hermes/hermes-agent`) at HEAD `04eb00cef7`; release floor v0.21.6 = commit `818c13be`.
- **Proof boundary:** unit tests use fakes only. They prove engine logic, not live gateway delivery. Live delivery is proven separately by the orchestrator.
- **Stop conditions (stop and report, do not improvise):** a Hermes seam described here does not exist or behaves differently at `04eb00cef7`; a design rule here conflicts with Hermes code; you would need to edit anything outside this repository; tests require network.
- **Evidence path:** write your unit report `U<n>-report.md` to the orchestrator's artifacts folder (files changed, test counts, red→green evidence for decisional tests, deviations with reasons, open questions).
- **Secret boundary:** never read `~/.hermes/.env`, `~/.npmrc`, or any credential file. No network calls in code paths exercised by tests.
- **Git:** read-only git only (status/diff/log). The orchestrator commits. Never run the system `hermes` CLI. Never write under `~/.hermes`.
- **Never spawn sub-agents.** One coherent owner per unit.

## 1. Product rules (non-negotiable)

1. Every wake runs inside the conversation that armed it, on that session's model, via `ctx.inject_message(text, session_key=…)`. No subagents, no fresh cron sessions, no side-model calls, no `origin=` argument anywhere.
2. v0.1 delivers only into **messaging-gateway DMs** (Telegram, Discord, Slack, …). Arming from CLI, TUI or Desktop sessions, or in group chats while `dm_only` is on, is refused with a clear reason. (CLI injection interrupts the user's turn; TUI/Desktop injections are stored as human rows without silence suppression — see §3.)
3. The model never types sentinels. Silence is decided by a structured `pulse respond` verdict; the plugin's `transform_llm_output` hook rewrites the final text to exactly `[SILENT]`.
4. No destination parameter exists in any tool schema. The target is the session that armed the wake.
5. The user sets bounds (plugin settings). The agent moves freely inside them, may tighten or switch itself off, never widens them. Every clamp is reported in the tool result.
6. Deterministic gates run before any model call. Time and quiet hours, caps, busy, estop, unanswered limit and probe fingerprints all cost zero tokens.
7. Durable: no in-memory timers. Wall-clock deadlines in SQLite; the engine survives restarts, clock jumps, sleep and compaction.
8. Stdlib only at runtime (plus Hermes-provided `croniter`/`psutil`, imported lazily; if missing, only the kind needing them is refused). No `pyproject.toml`. `register()` is import-light and network-free.
9. All times are computed through an injectable `Clock` (wall `now()` epoch seconds + `monotonic()`), so tests control time.

## 4. Data model (`heartbeat2/store.py`)

SQLite file `<home>/plugin-data/heartbeat2/pulse.db`, WAL, `busy_timeout=5000`, `BEGIN IMMEDIATE` for claims. Schema version in `meta`. Every state transition is a compare-and-swap (`UPDATE … WHERE id=? AND state=?` must affect exactly 1 row).

- **wakes**: id, session_key (immutable target), platform, chat_type, chat_id, armed_session_id, creator (`user|agent`), created_in (`human_turn|wake_turn|command`), parent_wake_id, depth, title (≤80), note (≤2000, self-contained instruction to future self), reason (≤280), scratch (≤4000), kind, trigger_json, probe_state_json, deadline_at, base_interval_s, eff_interval_s, pacing_min_s, pacing_max_s, babysit (bool), urgent (bool), cancel_on_reply (bool), max_fires, expires_at, status (`active|paused|proposed|done|cancelled|expired|failed|orphaned`), status_reason, next_due_at, last_fired_at, fires, model_turns, gated_skips, noop_streak, ignored_streak, error_streak, delivered, engaged, tokens_in, tokens_out, created_at, updated_at, version.
- **occurrences**: PRIMARY KEY (wake_id, dedupe_key). dedupe_key: `t:<scheduled_for>` for time wakes, `e:<sha1(event identity)>` for events/probes, `s:<episode_id>` for silence. state: `pending → claimed → started → done` plus terminal `skipped(reason) | missed | dead | interrupted | orphaned | superseded`. Fields: attempt, epoch, pid, claimed_at, started_at, ended_at, payload_json (coalesced events, ≤8 KB, ≤20 items), outcome, notify, summary, summary_hash, next_check_s, force_silent, delivered, tokens_in, tokens_out, error.
- **events** (inbox; any process writes, poller consumes): seq autoincrement, kind, session_key NULL, chat_id, payload_json ≤4 KB, dedupe_key UNIQUE, created_at, consumed_at.
- **sessions**: session_key PK, platform, chat_type, chat_id, current_session_id, last_human_at, last_activity_at, episode_id, unanswered_count, busy_since, enabled (`/pulse off`), paused_until, first_notice_sent, last_wake_turn_at, limits_fingerprint.
- **ledger**: (day, wake_id) → fires, gated_skips, governor_skips, model_turns, noops, valuable, delivered, engaged, ignored, tokens_in, tokens_out, errors.
- **meta**: schema_version, epoch, poller_pid, poller_started_at, last_tick_at, last_error, last_gc_at.

## 5. Wake kinds (`heartbeat2/model.py`, `schedule.py`, `probes.py`)

- Time: `at` (ISO-8601, `+20m`, `in 2h`, `tomorrow 09:00` in user tz), `every` (duration, optional `at HH:MM` anchor), `cron` (croniter; lazily imported), `self` (agent-paced via `next_check`, clamped to pacing min/max).
- Silence: `owner_silent` (`after` duration; fires at most once per silence episode; episode = from one human message to the next; wake turns, bot replies, internal events never reset it).
- Probes (deterministic, zero model cost until they fire): `file` (stat-poll path: change of mtime/size/inode; optional regex on appended lines), `process` (pid exit; guard pid reuse with create_time via psutil), `url` (GET ≤256 KB, 10 s timeout, fire on change or regex match), `command` (argv, no shell, 30 s timeout, must match the `probe_commands` allowlist by prefix; `fire_on: change|success|failure|json`; json form prints `{"fire": bool, "message": str, "state": obj≤16 KB}`, state saved only on a successful fire).
- Events: `kanban_completed`, `kanban_blocked`, `kanban_worker_exited`, `subagent_done`, `api_error` (aggregated, cooldown 30 min), `reaction` (Telegram; optional `emojis` filter), `message_edited`.
- Any probe/event wake may set `deadline`: if nothing fired by then, it fires once with "deadline passed — nothing happened" ("silence is not success").
- `babysit` flag (time `every`/`self` only): allowed only when created_in = human_turn; interval ≥5 min, expires ≤4 h, max_fires ≤24; ends on first `notify=true` or 3 consecutive `no_change`.

## 7. Agent tool `pulse` (`heartbeat2/tool.py`)

One tool, `action` enum: `create | list | update | pause | resume | cancel | respond | off`. JSON schema (keep description ≤600 chars; total schema ≈450 tokens):
- `create`: `title`, `note` (required), `reason`, `trigger` {`kind` (required), `at`, `every`, `cron`, `after`, `path`, `pattern`, `pid`, `url`, `command` (array of argv strings), `fire_on`, `event`, `emojis`, `check_every`, `deadline`}, `until` {`expires`, `max_fires`, `owner_replies` (bool → cancel_on_reply)}, `pacing` {`min`, `max`}, `babysit` (bool), `urgent` (bool).
- `update` (id + any create field; may change kind = "convert to watcher"), `pause`/`resume`/`cancel` (id or "all"), `list` (this session), `off` (agent switches HeartBeat off for this chat; only the user can turn it back on).
- `respond`: `outcome` (`no_change|progress|done|blocked|needs_attention`), `notify` (bool), `summary` (≤280), `next_check` (duration, for `self`/paced wakes), `scratch` (≤4000, replaces). Valid only while an occurrence is in flight for this session (else error). Last call wins. Scratch/next_check commit only when the turn ends without failure.

Permission matrix (decisional — red tests first):
- Resolve session from `get_current_session_key()`; refuse `"default"`/missing. Refuse non-gateway platforms (cli/tui/desktop/api_server/cron) with reason. Refuse groups when `dm_only`.
- `create` requires `enabled`, `agent_can_create != no`, `allow_gateway_injection`, caps, and inside a wake turn: depth ≤ `max_rearm_chain`, ≤1 child per wake turn, and a turn carrying an untrusted payload cannot create recurring wakes or watchers.
- Agent may update/resume/cancel/pause only its own items in this session; user items only during a human turn. Pause/cancel/off (de-escalation) always allowed on agent items.
- Never writes settings. Every clamp listed in the result: e.g. `"clamped": {"every": "2m → 60m (agent_ungated_floor)"}`.
- No `target`, `session`, `chat`, `platform`, `model` parameter exists (schema test).

## 8. Hooks / intake (`heartbeat2/intake.py`)

All hooks fail open (catch everything, log), do a few ms of SQLite work, return None unless stated.
- `post_gateway_admission(session_key, platform, source, message_id, text, …)`: upsert session (platform, chat_type, chat_id), `last_human_at = now`, new episode id, `unanswered_count = 0`, mark engaged on recent delivered occurrences within the window, cancel `cancel_on_reply` occurrences/wakes, write a `human_message` event. Return None.
- `pre_command` (gateway): count as human activity.
- `gateway_platform_event(event_type, payload, …)`: reaction / message_edited → map chat_id → session_key via sessions table; human activity; event row.
- `pre_llm_call`: bind session_id ↔ session_key; set busy_since. If `user_message` contains marker `⟦pulse o:<occ> a:<attempt>⟧` → occurrence `started` (stale attempt → superseded + force_silent; owner replied since claim and cancel_on_reply → superseded + force_silent); register in-flight. Else (human turn): `last_activity_at`; return context ONLY when there is something to say: presence line (if enabled and items armed), a pending governor card, a "N wakes were late / scheduler was stalled" note, a limits-changed-outside-/pulse note — each shown once.
- `post_api_request`: add usage tokens to the in-flight occurrence.
- `transform_llm_output(text, session_id, …)`: if an occurrence is in flight for this session and (`notify == false` or `force_silent` or superseded or no respond and text is a bare silence-ish reply) → return exactly `"[SILENT]"`. If notify=true and summary hash duplicates a delivery for this wake in the last 24 h → `"[SILENT]"` and mark force_silent. Otherwise None.
- `on_session_end`: clear busy; finalize in-flight occurrence (outcome `unreported` if respond never called; delivered = notify and not silenced; unanswered_count += 1 if delivered); run governor; signal poller.
- `agent_loop_stopped`: in-flight → `interrupted` (never re-run).
- `on_session_reset(old, new)`: orphan wakes of the old session (status `orphaned`, shown once at next human turn).
- `kanban_task_completed|kanban_task_blocked|on_kanban_worker_exited|subagent_stop|api_request_error`: insert event rows (any process).

## 9. Poller (`heartbeat2/poller.py`, `registration.py`)

- `register()` starts ONE daemon bootstrap thread per `ctx._manager.scope_key` (module-level dict guard). Thread binds `set_hermes_home_override(home)`, waits (2 s polls) for `has_gateway_message_injector` and no CLI ref, then takes non-blocking `flock` on `<db dir>/poller.lock` (standby retry 30 s). In CLI/cron/TUI/dashboard processes it idles forever at negligible cost. `ctx.on_unload` (if available) stops it. Never start work inside `register()` itself.
- Tick every 5 s (monotonic spacing; deadlines in wall time). Each tick: write `meta.last_tick_at`; detect wall gap > 3 ticks (sleep/App Nap) and log.
- Order: (1) global enabled + `check_paused` → if paused, consume nothing, keep ticking; (2) ingest events → match wakes (kind, filter, session scope) → `INSERT OR IGNORE` occurrence or append to the existing pending one (coalesce ≤20 items); (3) due probes (pool of 4, timeouts) → unchanged = `gated_skips+1`, no occurrence; (4) due time wakes → occurrence `t:<next_due_at>`, then `next_due_at = now + eff_interval` (jittered ±10 % for every/self; croniter next for cron) — missed ticks collapse to ONE; one-shots later than `catch_up_hours` → `missed`, reported once; (5) `owner_silent` → `s:<episode>`; (6) dispatch.
- Dispatch gate order per pending occurrence (each skip records a reason; zero model cost): wake active/unexpired/under max_fires → cancel-on-reply → session enabled / paused_until (defer) → dm_only / messaging gateway → provider unavailable (defer) → quiet hours (session override and configured range; defer one-shots to quiet end; skip recurring ticks) → unanswered mute (agent-created and check-in wakes) → daily caps + global flood (5 injections/min) + error ladder `not_before` → session busy (defer; NEVER inject into a busy session — the core busy FIFO is in-memory and lossy) → wake spacing → one in flight per session → claim (CAS pending→claimed, epoch, pid, attempt+1) → render wake text → `ctx.inject_message(text, session_key=…)`. Session-paused, provider-unavailable and quiet-hour windows are checked before dropping gates (unanswered and daily caps); deferred occurrences face every gate again when the window ends. False → refund to pending with ladder 30 s→60 s→5 m→15 m→60 m; after 5 → `dead`, error_streak+1.
- An active one-shot with no next due and no live occurrence terminates through `terminal_one_shot` when its latest non-superseded occurrence is `skipped` (final gate), `interrupted`, `dead` or `missed`. It becomes `failed` with its cause; `cancel_on_reply` becomes `cancelled` / `owner_replied`. Paused wakes and `wake_inactive` skips never fail through this path. Tool pause supersedes pending/claimed occurrences and keeps started turns; command and tool resume share a fresh one-shot dedupe key at max(stored due or now, now).
- Ack: claimed but not `started` within 10 min (`claim_ttl`) → refund, attempt+1; attempt > 3 → `dead` + reported. `started` but no `on_session_end` (crash) → `interrupted`, never re-run.
- Reconcile on poller start (new epoch): claimed → pending; started without end → interrupted; recurring wakes re-anchor at now; busy flags cleared; probes compare against stored baseline (a change during downtime fires exactly once).
- GC hourly: keep 200 occurrences per wake, 7 days of consumed events, `ledger_days` of ledger.
- Liveness: `/pulse status` reports alive (last tick ≤ 3 ticks) / stalled since X / not running + reason (no gateway in this process, injection disabled, lock held elsewhere, last_error). `pre_llm_call` on the gateway restarts a stalled thread (> 3 min) and adds one late-wakes line.

## 10. Governor (`heartbeat2/governor.py`)

- Value of a finished model turn: 1 for outcome `progress|done|needs_attention`, or a delivered message engaged within `engagement_window_hours`; 0 for `no_change|blocked|unreported`, silenced, deduped or ignored.
- `noop_streak` (+1 on value 0, reset on 1); `ignored_streak` (delivered, not engaged in window); `error_streak`.
- Backoff for recurring time wakes: `eff = clamp(base × factor^max(0, noop_streak − (noop_slowdown_after−1)), floor, min(max_backoff, pacing_max))`. For cron: skip the next `factor^k − 1` scheduled times as `skipped:governor`. For `self`: honour `next_check` but floor it at the backoff value once the slowdown threshold is reached. One value-1 outcome snaps back to base.
- At `suggest_gate_after`: the next wake text adds one hint: convert to a `file|process|url|command` watcher via `pulse update`, push next_check out, or cancel.
- Auto-pause when noop_streak ≥ `noop_pause_after`, ignored_streak ≥ `ignored_pause_after`, error_streak ≥ `error_pause_after`, or value ratio < 0.1 over ≥12 of the last 20 runs → status `paused`, reason `governor:<rule>`; ONE card at the next human turn (via `pre_llm_call` context) and in `/pulse`: keep / slow / stop / convert. Never an unprompted message.
- Babysit wakes: end on first notify=true or 3 consecutive no_change.
- Ledger rollups per day and wake.
- `max_unanswered` mutes agent-created and check-in wakes after the configured number of delivered unprompted messages without a human reply. Every owner-created wake is exempt, urgent or not; quiet hours, caps, busy, spacing and the provider gate still apply.

## 13. Invariants (each MUST have a named test, red-first for decisional modules)
